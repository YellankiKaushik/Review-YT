# Contributing

Develop new work from the functional requirements. Do not import the historical application's implementation or pretend its contributions did not occur. Disclose external sources and preserve applicable notices. Keep deterministic source fixtures under tests and never disguise them as live API results.

Use a branch with substantive commits, run the commands in README, and explain user-visible behavior and actual verification. Do not commit `.env`, raw source snapshots, credentials, databases or temporary browser captures. Curated, labeled documentation screenshots in docs/assets are an intentional exception. The maintainer MIT decision is recorded; preserve its eligible-material scope, all upstream notices and the disclosed provenance uncertainty. New concrete rights issues still require resolution before distributing affected material. Commit identities and dates must reflect actual work; no artificial contribution history is permitted.


Use npm ci with the root lockfile. Keep paid inference/fallback disabled in tests. Run scripts/verify.py, scripts/check_docs.py and the optimized production verifier before release. Submit a PR, inspect CI/available preview evidence and keep production changes within the approved scope. Record genuine results in the current report; archive dated evidence rather than deleting it.
